Line-by-Line Breakdown
function Button(){

Declares the Button component function. Every time state updates, React re-runs this entire function from top to bottom.

const [isButtonOn, setIsButtonOn] = React.useState(true);

Initializes state isButtonOn to true on the first render. On subsequent re-renders, React gives isButtonOn the latest committed state value.

let buttonText = 'ON';

Bug / Redundant local variable: On every single render, buttonText is reset back to 'ON'. Even if handleClick mutated buttonText during a click, the very next re-render triggered by setIsButtonOn(...) wipes that mutation out and sets buttonText right back to 'ON'. Instead of mutating a local variable, buttonText should be derived directly from isButtonOn during render.

Event handler function that runs when the button is clicked.

Commented-out attempt to mutate buttonText. Because isButtonOn is a stale snapshot from the current render, !isButtonOn checks the old value before the re-render happens.

Checks the current render's value of isButtonOn (true on the first click).

Clean Fix
JavaScript
function Button() {
  const [isButtonOn, setIsButtonOn] = React.useState(true);

  function handleClick() {
    setIsButtonOn(!isButtonOn);
  }

  return (
    <button
      type="button"
      className="button"
      onClick={handleClick}
    >
      {isButtonOn ? 'ON' : 'OFF'}
    </button>
  );
}
Core Takeaway
In React, UI labels should be derived from state during render (isButtonOn ? 'ON' : 'OFF'), not stored in a separate let variable and manually mutated inside an event handler.
